# 店铺批量导入规范

## 1. 导入方式

管理端先选择目标学校，再通过 `POST /api/v1/admin/stores/import` 上传 CSV 或 XLSX。导入采用单事务原子写入：任何一行校验失败，整批不写入。

接口使用 multipart 表单：

- `file`：CSV 或 XLSX 文件。
- `schoolId`：目标学校 ID。平台管理员可选择任意学校，学校管理员只能使用绑定学校。

## 2. 文件要求

| 项目 | 规则 |
| --- | --- |
| 文件类型 | `.csv`、`.xlsx` |
| 文件大小 | 不超过 5 MB |
| 数据行数 | 1–1000 行，不含表头 |
| CSV 编码 | UTF-8，可带 BOM；分隔符为英文逗号 |
| XLSX 工作表 | 读取第一个工作表，首行为表头 |
| 空行 | 完全空白的行忽略；部分填写的行正常校验 |
| 图片 | 表格中只填写图片 URL，不接受图片文件或二进制内容 |

## 3. 中文模板字段

表头必须按以下顺序填写：`食堂,店铺位置,店铺名称,店铺图片`。

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `食堂` | 是 | 目标学校下已启用的食堂名称，也支持填写区域编码 |
| `店铺位置` | 是 | 店铺在食堂内的位置或地址，最长 255 字符 |
| `店铺名称` | 是 | 店铺名称，最长 120 字符 |
| `店铺图片` | 是 | HTTP(S) 图片 URL，最长 2048 字符；必须是系统上传图片后返回的媒体地址 |

学校、店铺编码、分类和状态不放在模板中：学校来自页面选择，店铺编码由系统稳定生成，分类默认为“未分类”，导入后的店铺默认上架。

## 4. 新增与更新规则

1. 系统根据目标学校、食堂、店铺名称和店铺位置生成稳定的店铺编码。
2. 同一文件中“食堂 + 店铺位置 + 店铺名称”重复时整批失败。
3. 再次导入相同组合时更新店铺名称、位置和图片，不会产生重复店铺。
4. 图片 URL 必须指向系统已上传的媒体对象；外部任意图片地址不能直接写入店铺图片。
5. 所有成功导入的店铺状态为 `active`，评分、评论、收藏和历史数据不受影响。

## 5. 示例 CSV

```csv
食堂,店铺位置,店铺名称,店铺图片
南食堂,一楼 01 号,示例自选餐,https://eat.unilinkcore.cn/media/eat-anything-test/stores/example/cover.jpg
北食堂,二楼靠东侧,示例面馆,https://eat.unilinkcore.cn/media/eat-anything-test/stores/example/noodle.jpg
```

旧版带 `storeCode`、`schoolCode`、`areaCode` 等字段的文件仍保留后端兼容解析，但管理页面下载的新模板和推荐格式均为上述中文模板。
